# kztgholders

Telegram-бот, который следит за числом холдеров жетона **TGCOIN (KZTG)** —
тенге-стейблкоина на TON — и постит обновления в канал:

- Раз в день (по расписанию `DAILY_CRON`): если число холдеров не изменилось,
  пишет `⏳ В тоне все еще N казах(ов)..`
- Сразу при изменении числа холдеров (проверка каждые `POLL_CRON`, по
  умолчанию раз в 10 минут): пишет `🔥 В тоне появился второй казах` (или
  сообщение об уменьшении, если холдеры ушли).

## Источник данных

Количество холдеров берётся из [tonapi.io](https://tonapi.io):
`GET /v2/jettons/{address}/holders`, поле `total`.

Так как жетон новый и холдеров мало, ответ вида "0 холдеров" или сетевая
ошибка/некорректный JSON считаются подозрительными: запрос повторяется с
задержками (5с → 15с → 45с, всего `TONAPI_MAX_ATTEMPTS` попыток). Если после
всех попыток так и не удалось получить достоверное значение — цикл проверки
просто пропускается (без спама и без бесконечного ретрая), следующая попытка
будет на следующем запланированном тике.

## Переменные окружения

См. `.env.example`. Основные:

| Переменная | Назначение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота |
| `TELEGRAM_CHAT_ID` | id канала (см. ниже про формат) |
| `JETTON_ADDRESS` | адрес жетона (по умолчанию KZTG) |
| `TONAPI_KEY` | опционально, ключ tonapi.io для более высокого рейт-лимита |
| `POLL_CRON` / `DAILY_CRON` | cron-расписания проверки/дневного поста |
| `TZ_NAME` | таймзона для cron (по умолчанию `Asia/Almaty`) |
| `STATE_FILE_PATH` | путь к файлу состояния (см. Persistence) |

### Формат `TELEGRAM_CHAT_ID`

Бот уже добавлен в канал с id `4376417384`. В Bot API числовые id каналов
обычно передаются с префиксом `-100`, поэтому в `.env.example` он указан как
`-1004376417384`. Если бот при отправке получит ошибку `chat not found`,
проверьте фактический id через `getUpdates`/`getChat` и поправьте переменную.

## Persistence (важно для Railway)

Бот хранит в `STATE_FILE_PATH` последнее известное число холдеров и дату
последнего дневного поста — это нужно, чтобы:
- не дублировать дневной пост при рестарте контейнера;
- не разослать повторное "холдеры изменились" после редеплоя.

Файловая система Railway по умолчанию эфемерна — при редеплое `data/`
пропадёт. Чтобы состояние переживало редеплои, подключите
[Railway Volume](https://docs.railway.app/reference/volumes) и укажите
`STATE_FILE_PATH=/data/state.json` (путь внутри смонтированного volume).

Без volume бот всё равно будет работать корректно — просто после каждого
редеплоя он один раз "молча" переустановит текущее число холдеров как базовое
(без поста), и дальше продолжит следить за изменениями.

## Локальный запуск

```bash
npm install
cp .env.example .env   # заполнить TELEGRAM_BOT_TOKEN и остальное
npm start
```

## Деплой на Railway

1. Создать проект на Railway из этого GitHub-репозитория
   (`data-will-be-here/kztgholders`).
2. Задать переменные окружения из `.env.example` (как минимум
   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`).
3. (Рекомендуется) подключить Volume и смонтировать в `/data`, выставить
   `STATE_FILE_PATH=/data/state.json`.
4. Деплой — Railway сам определит Node.js проект и запустит `node src/index.js`
   (см. `railway.json`).

Бот не принимает входящие сообщения и не использует long polling/webhook —
он только раз в цикл дергает tonapi.io и шлёт `sendMessage` в канал, так что
никаких конфликтов с несколькими инстансами не будет (кроме дублирования
постов, если случайно запущены две копии одновременно).
